# Как добавлять работы

После подключения редактора разработчиком зайдите на https://app.pagescms.org. В приглашении будет указана ваша почта. Редактор можно использовать без знания Git и кода. До первой настройки доступа вход и публикация ещё недоступны.

1. Откройте Clever Knots и раздел **Работы**.
2. Нажмите **Добавить**. Напишите название и описание. Выберите технику.
3. В поле адреса напишите короткое название латиницей через дефис: например `sumka-makrame`. Это адрес работы, не её видимый заголовок.
4. Добавьте фотографии. Первая фотография станет обложкой. Для каждой коротко опишите, что на ней изображено.
5. Цена и доступность необязательны. Их можно оставить пустыми.
6. Включите **Показывать на сайте**. Для избранной работы включите **Показывать на главной**. Если избранных несколько, на главной появится первая по порядку.
7. В поле порядка укажите число. 10 будет выше 20. У каждой работы лучше своё число.
8. Сохраните. После включения публикации сайт обновится автоматически после успешной сборки. Это занимает некоторое время; обновление не мгновенное.

Чтобы временно скрыть работу, выключите **Показывать на сайте** и сохраните. Для удаления откройте работу и выберите удаление. История остаётся в GitHub, разработчик сможет восстановить файл.

**Тексты сайта** редактируются в отдельном разделе. Название Clever Knots сохраняйте в таком написании. Подписи и рассказ о мастерской можно менять.

## Фотографии

Лучше подходят снимки у окна, на спокойном фоне, без рекламных надписей. Загружайте JPG, PNG, WebP или AVIF. Рекомендуемый размер — до 2000 пикселей по длинной стороне и до 1 МБ. Оригиналы с телефона храните отдельно: редактор сохраняет загруженный файл в репозиторий, и сжатие сайта при сборке не уменьшает старые файлы в истории Git.

Если фотография слишком большая, попросите помочь уменьшить её перед загрузкой. Для разработчика есть команда `npm run optimize:media`; она не требует переименовывать уже добавленные файлы.

Если сайт не обновился или появились ошибки, не удаляйте фотографии повторно: сообщите разработчику, какую работу вы меняли.
